# Deployment Architecture

## Overview
The SaaS consists of three main components:

1. **Next.js Front‑end** – statically generated site + client‑side SPA for the ERP, POS and KDS interfaces.
2. **Node.js API** – Express server that hosts all business‑logic, authentication, RBAC, real‑time events and background jobs.
3. **Managed Services** – PostgreSQL (Supabase), Object Storage (Supabase Private Bucket), Redis (managed), and a real‑time channel (Supabase Realtime/WebSocket).

### Environment Separation
| Environment | Domain | Next.js URL | API URL | DB | Redis |
|------------|--------|-------------|---------|----|-------|
| Development | `dev.mehrmaan.local` | `https://dev.mehrmaan.local` | `https://api.dev.mehrmaan.local` | Supabase **dev** project | Supabase **dev** Redis |
| Staging    | `staging.mehrmaan.com` | `https://staging.mehrmaan.com` | `https://api.staging.mehrmaan.com` | Supabase **staging** project | Supabase **staging** Redis |
| Production | `www.mehrmaan.com` | `https://www.mehrmaan.com` | `https://api.mehrmaan.com` | Supabase **prod** project | Supabase **prod** Redis |

All three environments have isolated credentials (separate Supabase projects, separate Redis instances) and never share secrets.

## Traffic Flow
1. **HTTPS termination** at the CDN (CloudFront / Vercel Edge).
2. Requests to `/api/*` are proxied to the API Gateway which forwards to the Node.js container fleet (ECS/Fargate). TLS is end‑to‑end.
3. Real‑time updates (order creation, kitchen ticket status, inventory changes) flow via **Supabase Realtime** (PostgreSQL logical replication) and are also pushed over a WebSocket server hosted alongside the API.
4. Static assets (images, PDFs) are stored in a **private Supabase bucket** and accessed through signed URLs generated by the API.
5. The **Redis** cluster is used for session storage, rate‑limit counters and a small job queue.
6. **Background workers** poll a `outbox` table (transactional outbox pattern) and publish events to the WebSocket server and to external services (e.g., email, Slack).

---

**Key Security Points**
- No secret is ever stored in the front‑end bundle.
- All environment variables are injected at runtime by the container orchestrator.
- RLS policies enforce tenant isolation at the DB level.
- MFA, rate‑limit and JWT revocation are enforced by the API before any data access.
